# BGM 节奏分析与卡点

只有用户指定了强节奏 BGM，或分镜明确要求卡点时启用本流程。没有指定 BGM 时，不为了“看起来专业”强行做节拍分析。

## 分析顺序

1. 保留原始音频，不覆盖用户文件。
2. 记录曲名、来源、授权、下载日期、采样率和时长。
3. 分析 BPM、拍点、相位、瞬态和能量段；不要只相信播放器显示的 BPM。
4. 生成 `analysis/beat_data.json`，至少包含：

```json
{
  "bpm": 0,
  "t0": 0,
  "beatInterval": 0,
  "beats": [],
  "hits": [],
  "sections": []
}
```

5. 分镜先确定叙事，再用拍点调整切镜和关键动作；不能为了卡拍牺牲字幕可读性或证据对应关系。
6. 使用 `beatF(n)` 或等价函数表达时间线，不把同一首音乐的拍点散落成裸帧号。
7. 渲染后从成片音轨回测切点，记录设计帧与实际瞬态之间的误差。

## 适用规则

- 密集鼓点段减少 SFX，只给画面独有的动作配音效。
- 大动作最多选择少量强拍，避免每个镜头都 slam。
- 素材内部峰值要对齐目标拍点，不能只按音频文件头对齐。
- 结尾落在真实瞬态或确认过的余韵位置，不钉在尾音的随机位置。
- 换 BGM、改变 BPM、改变镜头顺序或改变镜头时长后，重新生成 beat data 并重对时间线。

## 交付记录

在 `design-spec.md` 或 `audio-plan.md` 中记录：

- 是否启用节拍流程。
- BPM、相位和分析文件。
- 采用的拍点、弃用的拍点和原因。
- 渲后回测误差。
