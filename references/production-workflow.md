# 制作工作流

## 1. 解析口播稿

保留用户正文，不擅自改变观点。把括号内容拆为画面提示，把正文按语义分成：钩子、承诺、概念、证据、操作、比较、提醒、结论。

对每一句建立记录：

| 字段 | 内容 |
|---|---|
| 旁白 | 实际要说的句子 |
| 预计时长 | 结合句长、停顿和操作速度估算 |
| 证据 | 网页、录屏、终端、模型输出、官方图标或概念图 |
| 画面任务 | 观众这一刻必须看到什么 |
| 风险 | 缺素材、需脱敏、可能过时或不能验证 |

脚本提到产品能力、效果或结论时，必须能绑定真实证据。括号提示可以优化，但不能当成需要朗读的文字。

## 2. 建立设计 spec

在 `design-spec.md` 写清：

- 一句话核心结论、受众、平台、画幅、总时长与音频要求。
- 必须展示的功能与证据来源。
- 色板、字体、字幕、圆角、背景、运动速度和禁用项。
- 数据口径：公开、虚构、脱敏或冻结。
- 本片采用与弃用的 Shotcraft 镜头语法及原因。

本技能默认使用 `$video-shotcraft` 的自主自由创作路线。扫描镜头卡 frontmatter，选中卡后必须读取卡片全文和准确 demo TSX，不凭卡名重写一份近似动画。

## 3. 生成分镜

每镜头只承担一个叙事任务。完整分镜至少包含：

| # | 时间 | 旁白 | 画面与证据 | 主动作 | 素材 | 字幕 | SFX |
|---|---|---|---|---|---|---|---|

规则：

- 每 1–3 秒出现有效信息变化；静态卡片不能长时间占满叙事。
- 真实动态证据优先，AI 测评内容目标占比约 65%–80%。
- 开头 10 秒用“钩子 → 三问题/核心冲突 → 这条视频能带来什么”推进。
- 不用微型标签解释镜头；需要解释时改成大标题、字幕或下一镜头。
- 第一次制作该主题时可输出开头约 40 秒预览供用户检查；用户要求直接完整制作时不因此暂停。

## 4. 素材采集

- 优先使用用户文件、真实官网、官方图标、真实操作录屏和模型真实输出。
- 复刻既有页面必须用真实截图/录屏，不手搓近似界面。
- 真实页面采集建议输出 2x 全页图、关键元素切片和 `layout.json`。
- 隐藏账号、通知、密钥、内部地址和个人数据。API Key 只使用明确脱敏的示意值。
- 不猜第三方 API 字段；需要付费生成或发布时先获得用户授权。
- 素材缺失且无法安全补齐时，输出最小补录清单，不能用静态卡片掩盖缺口。

## 5. Remotion 实现

默认 1920×1080、30fps，按 `SHOTS` 时间线管理镜头。可从 `assets/golden-reference/src/` 参考以下部分：

- `components/Common.tsx`：色板、字体、字幕切分、浏览器窗口、鼠标与确定性缓动。
- `timeline.ts`：按口播段落计算全局帧号。
- `EditorialScenes.tsx`：浅色编辑卡片、概念图和结构解释。
- `ShotcraftScenes.tsx`：深色动效与真实操作呈现。
- `InfistarVideo.tsx`：场景注册、相对 SFX 钉帧和 BGM 开关。

新项目必须替换所有示例项目专属文本、页面和图标。保留通用样式时，同时移除 `EMPHASIS` 中与当前主题无关的关键词。

每个镜头完成后至少渲染三个静帧检查：入场中、动作峰值与落定帧。开头、3D 推近、真实 UI、字幕密集和转场接缝属于高风险镜头。

## 6. 音频

- 用户明确暂不配音：不生成语音，按预计口播节奏保留字幕、SFX 与可选 BGM。
- 用户未排除配音：口播稿成片默认生成中文旁白，按 `AGENTS.md` 的参考声线执行；先确认服务支持参考音频或存在真实 voice ID。涉及付费调用时仍需在提交前获得授权。
- 画面锁定后再钉 SFX，使用相对帧表达式。时间线变化后全表重对。
- 音效以 whoosh、impact、riser、真实点击/键盘和轻量 sparkle 为主，避免游戏提示音。
- BGM 只做能量底，不覆盖旁白。使用 `bgm` input prop 从同一时间线导出两版。

## 7. 渲染与交付

先渲染母版，再做兼容版：H.264 Main、yuv420p、BT.709 limited、30fps CFR、无 B 帧、faststart。不得只拼接旧片段冒充整片重渲；修改全局组件或时间线后必须完整渲染。

按 [终检清单](qa-checklist.md) 生成质量报告。没有独立审查 PASS 不交付。
