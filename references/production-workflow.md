# 制作工作流

默认采用自主自由创作：输入足够时连续完成各阶段，不逐阶段等待用户确认。以下情况必须暂停并请求用户决定或授权：画幅无法安全推断、需要登录或敏感数据、需要付费素材/配音/声音克隆、需要发布，或脚本事实无法验证。

## 0. 整理口播稿

先复制用户原稿为 `script-original.md`，按 [口播稿人性化处理](script-humanization.md) 生成：

- `script-revised.md`：实际旁白稿。
- `script-edit-notes.md`：修改原因、事实影响和待验证项。

括号内容拆成画面提示，不进入旁白和字幕。不要添加原稿没有的个人经历、测试结果、来源、用户反馈或产品承诺。脚本中无法验证的事实进入风险栏，不得靠语气把它说成确定结论。

## 1. 产品与执行约束

在写视频代码或采集最终素材前，只读检查：

- 主题、受众、目标平台和核心结论。
- 必须展示的功能、页面状态和证据。
- 项目技术栈、入口、路由、交互状态、外部依赖和数据风险。
- 当前 `AGENTS.md` 对输出、密钥、声音、网络、付费操作和发布的限制。

产出 `design-spec.md` 的产品简报、需求假设、数据口径和素材缺口。公开演示数据只有在确认其公开属性后才可保留；客户、个人、内部、实时或其他敏感数据必须虚构、脱敏或冻结。

## 2. 确定画幅和视觉方向

根据用户要求、平台或项目规则选择 `16:9 / 9:16 / 1:1`，写入：

- 比例、分辨率和 30fps。
- 标题与字幕安全区。
- 卡片数量上限和重排策略。
- 当前参考工程是否真正支持该画幅。

再从产品源码、网页 computed styles 或品牌材料提取字体、字号、行高、栅格、间距、圆角、表面色、正文色、强调色和材质。将采用和弃用的动效语法写入 `design-spec.md`。styleframe 可以使用少量安全预检素材，但不能代替最终素材采集。

## 3. 证据映射

把 `script-revised.md` 的每个结论绑定到真实证据、明确的概念图，或素材缺口：

| 旁白句子 | 结论 | 证据 | 来源/授权 | 数据口径 | 风险 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

真实网页、软件操作、终端、模型输出和官方素材优先。复刻既有页面时必须用真实截图或录屏，不手搓近似 UI；抽象概念才使用作者绘制的图形。

## 4. 镜头映射与分镜

先读 [镜头索引](shot-library.md)，再为每个叙事任务选择一个主要动效。镜头卡或参考场景只是运动语法，不是完整分镜。

完整 `storyboard.md` 至少包含：

| # | 时间/帧 | 旁白 | 证据与画面 | 主动作 | 镜头/源文件 | 素材编号 | 字幕 | 转场 | SFX | 风险 |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 |  |  |  |  |  |  |  |  |  |  |

要求：

- 开头 10 秒至少完成钩子、核心问题和路线承诺三次有效变化。
- 每镜只讲一个主要动效；一种显眼动效全片只当一次主角。
- 每 1–3 秒有叙事意义的变化；信息落定后保留可读停顿。
- 真实动态证据目标占比约 65%–80%。
- 字幕按语义和实际口播节奏切分，不让整段旁白直接压成一屏。

## 5. 最终素材采集

只有最终分镜和画幅策略确定后，才进行全量采集。完整阅读 [素材采集](asset-capture.md)，在制作目录建立 `assets/asset-manifest.md`。

复刻页面建议保留：

```text
public/media/<page>-fullpage@2x.png
public/media/<page>-<element>@2x.png
public/media/<page>-layout.json
public/media/<page>-capture-notes.md
```

每个素材记录来源、授权、采集日期、数据口径、分辨率和对应镜头。采集前隐藏通知、账号、内部地址、剪贴板和密钥；无法安全脱敏时列为补录清单并停止使用该素材。

## 6. Remotion 实现

当前仓库的 `assets/golden-reference/` 是 16:9 Agent Studio 主题示例工程。复制前先读：

- `assets/golden-reference/ASSET_MANIFEST.md`
- `assets/golden-reference/SHOT_INDEX.md`
- `assets/golden-reference/src/` 中对应的参考实现

新项目必须替换示例文本、URL、图标、页面和媒体。制作竖屏或方形视频时，按 `video-formats.md` 重排版式、字幕和坐标，不直接缩放横屏工程。

每个镜头完成后至少渲染三个静帧：入场中、动作峰值、落定帧。重点检查开头、3D 推近、真实 UI、字幕密集和转场接缝。时间线、全局组件或素材改动后完整重渲，不拼接旧片段。

## 7. 声音

完整阅读 [声音设计](sound-design.md)。用户指定强节奏 BGM 时额外阅读 [节拍卡点](music-beat-sync.md)：

- 用户明确不要配音时，不生成语音。
- 需要配音时，先确认已授权的声线、参考音频或 voice ID 可被目标服务支持。
- 声音克隆、付费配音、付费素材和发布都必须先获得明确授权。
- 画面结构基本锁定后再铺 BGM 和 SFX。
- SFX 用相对镜头起点或 `beatF(n)` 钉帧；镜头改变后全表重对。
- 启用 BGM 时从同一时间线导出带 BGM 和无 BGM（保留 SFX）两版。

## 8. 渲染、复核与交付

先渲染母版，再按 `qa-checklist.md` 做规格检查、抽帧检查、音频检查和隐私检查。使用 BGM 时确认两版视频的画面和 SFX 逐帧一致，只有 BGM 开关不同。

生成 `review-packet.md`，把当前版本的成片、关键帧、脚本、设计 spec、分镜、素材清单和清单交给不参与制作的独立审查上下文。完整阅读 [独立终检](final-review.md)；只有收到 `PASS` 才能交付。
